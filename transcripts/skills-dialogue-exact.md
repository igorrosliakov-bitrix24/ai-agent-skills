# Точная часть диалога о скиллах и общей библиотеке навыков

Ниже сохранён диалог без пересказа. Он нужен агенту, который будет проектировать и создавать общую библиотеку скиллов.

---

## Пользователь

Я хочу как-то автоматизировать создание таких обложек, чтобы не забыть, как правильно делать промпт. Пользуешься ли ты скиллами? Могу ли я как-то тебя это записать? Или помоги мне составить скилл какой-то универсальный для агентов и скажи мне, куда его разместить, чтобы все агенты, которыми я пользуюсь, смогли им пользоваться. Объясни мне вообще, как это работает.

## Ассистент

Да, и это как раз тот случай, где **скилл** действительно лучше обычного промпта.

Но сначала важный момент.

Есть три уровня "памяти", и их часто путают.

### 1. Один большой промпт

Например:

> Нарисуй обложку...

Каждый раз вставляешь его целиком.

Минусы:

- огромный;
- забываешь обновлять;
- копируешь вручную.

### 2. Пользовательские инструкции (Custom Instructions)

Это то, что знает только ChatGPT.

Например:

> Если я прошу придумать обложку, сначала помоги определить стиль.

Это работает **только в ChatGPT**.

Claude этого не знает.

Codex тоже.

### 3. Skill

Это уже почти мини-документация.

Например:

```text
skills/

cover_design/

    skill.md

    examples/

        habr.md

        wired.md

        cyberpunk.md
```

И агент умеет этим пользоваться.

Это гораздо мощнее.

### Я бы тебе сделал именно Skill

Например:

```text
cover_design/
```

Внутри:

```text
skill.md
```

И там написано:

> Когда пользователь просит сделать обложку, сначала НЕ генерируй промпт.
>
> Сначала помоги определить стиль изображения.
>
> Разбери будущую картинку по параметрам.
>
> После этого проверь поля, предложи недостающие варианты, собери единый промпт и только потом генерируй изображение.

Такой skill потом можно использовать практически везде.

### Я бы сделал ещё лучше

Я бы сделал сразу четыре skill:

```text
skills/

cover_design/

article_writing/

habr_review/

prompt_engineering/
```

Потому что это четыре вещи, которые ты делаешь постоянно.

`cover_design` умеет подобрать стиль, придумать композицию и собрать промпт.

`habr_review` умеет искать опечатки, проверять факты, слабые места и логические скачки.

`article_writing` умеет сначала делать план, потом черновик, потом улучшать.

`prompt_engineering` умеет превращать идеи в хорошие промпты.

### Где хранить

Я бы сделал GitHub-репозиторий:

```text
my-agent-skills/

README.md

skills/

cover_design/

skill.md

examples/

...

habr_review/

skill.md

...

article/

skill.md

...
```

Потом Claude Code, Codex, OpenCode, Cursor и Aider смогут использовать эту библиотеку.

Это становится личной библиотекой знаний, а не промптом, привязанным к одной модели.

Практически все задачи пользователя повторяются:

- написать статью;
- проверить статью;
- придумать обложку;
- сделать промпт;
- придумать архитектуру проекта.

Это рабочие процессы, поэтому их стоит хранить как библиотеку навыков.

## Пользователь

Как мне подключить этот репозиторий ко всем агентам, которые я использую?

## Ассистент

Универсально подключить репозиторий ко всем агентам одной кнопкой пока нельзя. Но Claude Code, Codex и OpenCode поддерживают формат `SKILL.md`, поэтому навыки можно хранить в одном GitHub-репозитории и подключить через символические ссылки.

Рекомендуемая структура:

```text
my-agent-skills/
├── README.md
└── skills/
    ├── cover-design/
    │   ├── SKILL.md
    │   └── references/
    │       └── prompt-template.md
    ├── habr-review/
    │   └── SKILL.md
    └── article-outline/
        └── SKILL.md
```

Каждый `SKILL.md` должен начинаться с YAML-заголовка:

```md
---
name: cover-design
description: Помогает придумать концепцию обложки, заполнить параметры изображения и собрать итоговый промпт для генератора.
---
```

Репозиторий можно клонировать один раз:

```bash
mkdir -p ~/agent-tools
cd ~/agent-tools
git clone https://github.com/ТВОЙ-ЛОГИН/my-agent-skills.git
```

Навыки будут лежать в:

```text
~/agent-tools/my-agent-skills/skills/
```

Для Codex:

```bash
mkdir -p ~/.agents
ln -s ~/agent-tools/my-agent-skills/skills ~/.agents/skills
```

Для Claude Code:

```bash
mkdir -p ~/.claude
ln -s ~/agent-tools/my-agent-skills/skills ~/.claude/skills
```

OpenCode умеет читать навыки из `~/.agents/skills/`, `~/.claude/skills/` и `~/.config/opencode/skills/`.

Итоговая схема:

```text
                GitHub
                   │
                   │ git pull
                   ▼
        agent-skills/
             │
      ┌──────┴────────┐
      │               │
      ▼               ▼
~/.claude/skills   ~/.agents/skills
      │               │
      ▼               ▼
 Claude Code      Codex
```

Обычные веб-чаты ChatGPT и Claude.ai локальный репозиторий автоматически не читают.

## Пользователь

## Ассистент

Самый удобный вариант — GitHub через Claude Code или Codex на компьютере пользователя. Агент получает доступ к папке проекта и авторизованному Git, после чего может создавать репозитории, делать коммиты, пушить изменения, создавать ветки и Pull Request.

Также обсуждалась структура общей библиотеки:

```text
personal-agent-skills/

README.md

AGENTS.md

skills/

    article-writing/

    article-review/

    cover-design/

    prompt-engineering/

    software-architecture/

    coding-standards/

    habr-style/

    japanese-learning/

    game-design/
```

Идея: сделать отдельный проект, а не набор случайных промптов.

## Пользователь

Я не понимаю, то есть у меня на компьютере как будто бы будут храниться ссылки, которые будут видеть агенты?

## Ассистент

Да. На компьютере хранится одна настоящая папка с репозиторием, а в стандартных папках агентов создаются символические ссылки на неё.

Например:

```text
agent-skills/

skills/

cover-design/
SKILL.md

habr-review/
SKILL.md

article-writing/
SKILL.md
```

Claude Code смотрит в:

```text
~/.claude/skills/
```

Codex смотрит в:

```text
~/.agents/skills/
```

Обе папки могут ссылаться на одну настоящую папку `agent-skills/skills/`.

Была предложена более широкая структура:

```text
AI/

skills/
    cover-design/
    article-review/
    article-writing/

templates/
    habr-article.md
    cover-prompt.md

references/
    visual-styles.md
    prompt-patterns.md
    habr-guidelines.md

examples/
    cover-examples/
    article-examples/
```

Так навыки могут ссылаться на общие шаблоны и примеры.
